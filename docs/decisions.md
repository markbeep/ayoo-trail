Lifts the D24 pause for these tasks only | Owner: "implement the base engine and the basic metrics"; scope chosen as M1 + M2 + route API + client hookup |
| D30 | 2026-11-18 | Slope is costed from a per-edge grade histogram (share of length in 9 signed grade bands, DEM sampled every ~10 m), not from average gain/len. Replaces splitting edges at elevation extrema (design v4) | Owner, after the averaging flaw was shown (500 m flat + 500 m at 30 % averages to 15 %); `layers.md` and design §13 already assumed a histogram |
| D31 | 2026-11-18 | Missing tags are inferred from the highway type: highway class stored per edge; surface inferred for roads (asphalt) and tracks (`tracktype`), paths stay unknown; the missing-`sac_scale` penalty applies only to `path`/`bridleway`. Inferred values are flagged. No road-class/traffic factor yet (Q24) | Owner, after untagged village roads were shown to cost the same as untagged forest paths |
| D32 | 2026-11-18 | Score = `100 · min(0.63 / mean_factor_default, 1)`, where `mean_factor_default` is route cost per metre under default weights without exclusion or repetition penalties. Non-saturating for real routes and stable when sliders move. Fixes the per-km units bug in design §8 | Owner chose the non-saturating score |
| D33 | 2026-11-18 | Elevation source is configurable behind one trait: swissALTI3D 2 m tiles (default) and DHM25 25 m ASCII grid (fast CH-wide builds). Both stay in the native Swiss grid | Owner: "Both, configurable" |
| D34 | 2026-11-18 | `REGION=demo` covers Wattwil–Ziegelbrücke: lat 47.10–47.34, lon 8.95–9.22 | Owner: "around wattwil/ziegelbrücke" |

| D36 | 2026-11-18 | The client gets a dev-only routing mode behind `?dev=route` (click waypoints → `POST /api/route`) for checking the cost model on real data. Not a product entry point; D13 stands | Owner chose "Server + client hookup" |
| D37 | 2026-11-18 | Technical defaults accepted with the plan: CSR adjacency section in `graph.bin`; snap over a segment R-tree with a profile-aware predicate; bridges/tunnels interpolate elevation; geometry Z densified where the DEM profile deviates > 3 m; forest from OSM multipolygons too (`landuse=forest`, `natural=wood` only); no GDAL (GeoTIFF via `tiff`, GPKG via `rusqlite`); server starts without a graph and `/api/route` answers 503 | Plan review 2026-11-18, approved by the owner |
| D38 | 2026-11-18 | The web client moves to SolidJS 2.0 (solid-js 2.0.1, @solidjs/web, @solidjs/vite-plugin, @lucide/solid) | Owner: "switch to solidjs 2.0. its new, but also optimized for AI use" |
| D39 | 2026-11-19 | Loop generation = triangle seeds at 12 headings (via points at θ±30°, radius r₀ = D/(3·1.3)), pulled to an anchor within r/3, legs routed with a shared repetition penalty, radius rescaled by D*/D up to 3 times, ranked by distance error, climb term and score, deduplicated at 0.5 shared-edge overlap. Replaces plan task 9's anchor ranking and task 10's anchor-insertion repair and offset refinement. The `/api/generate` LRU cache is deferred until latency is measured | Owner accepted the proposal: peaks are often off-trail, radius scaling converges predictably |
| D40 | 2026-11-19 | Default base map is an own-styled OSM vector map (OpenFreeMap tiles, OpenMapTiles schema, keyless, Europe-wide) whose colours follow the UI tokens. | D41 | 2026-11-19 | Base maps are exclusive; everything else (relief, trails, forest, snow, popular trails, path steepness, 360° view, sun/shade) is an overlay the user toggles independently on any base map. Resolves Q22 | Owner |
