| D70 | 2026-11-19 | Q25 steps 1–2. Loop generation searches a per-request region (`src/region.rs`): the nodes within 0.5 × the target distance of the start, in local ids, with every edge's cost stored as `flat + discount · graded` so one region serves every climb pressure. Per climb pressure it builds a shortest-path tree from the start and one into it. The first leg is read off the first tree; later legs run A* in the region with the start as an ALT landmark (`d(v, end) ≥ d(start, end) − d(start, v)` and `≥ d(v, start) − d(end, start)`, still valid under the repeat penalty). Legs with an end outside the region, or without a path inside it, fall back to the whole graph. Via points move onto the loop only for the loops that are kept (that took as long as all the searches). Loops are identical to before at Wattwil, Bichelsee, Zürich and Geneva (20 km, with and without a 1,200 m climb goal), and Bichelsee is unchanged. 20 km on one thread, release: Wattwil 169 → 45 ms, Bichelsee 138 → 54 ms, Zürich 1.33 → 0.30 s, Geneva 0.60 → 0.14 s; with the climb goal 1.5–5× faster too (Wattwil 117 ms, Zürich 0.76 s).
